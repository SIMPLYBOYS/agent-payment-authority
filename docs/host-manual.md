# 主持人手冊

給上台操作 demo 的主持人。照著做就能開場、跑一場、收場；出錯時查第 6 節，照「下一步」做。看不懂、或表上沒有的狀況，先停下，不要自己繞過。

兩種場地：

| | 本機 | Base Sepolia testnet |
|---|---|---|
| 指令 | `make demo-local` | `make demo-testnet` |
| 鏈 | 這台電腦上的測試鏈（anvil） | 公開測試網路 |
| 核准 | 已登記的裝置（PIN） | 已登記的裝置＋唸一句話 |
| 要輸入的 | 錢包的密語 | 登入密碼（sudo）、relayer 的密語、錢包的密語 |
| 錢 | 測試 USDC，不是真錢 | Circle 的測試 USDC，不是真錢 |

兩種都是 fake Agent（照劇本購物，不執行真的模型）。真的 Agent 另見 `docs/commercial-e1a.md`。

## 1 前一天

- [ ] 電腦插電、關掉自動睡眠與自動更新；Chrome 已登入 Google 密碼管理工具（核准用的 passkey 在裡面）。
- [ ] 本機彩排一次：`make demo-local`，資料研究室按「一起開始」，A、B 都核准、都付款完成。
- [ ] testnet 場：確認今天還沒用掉額度（第 2 節）；彩排盡量用本機，testnet 每一場都會用掉額度。
- [ ] 麥克風（testnet 唸句子用）：系統設定裡選好、測過音量。

## 2 開場前 30 分鐘

- [ ] 所有舊的終端機都已停下（Ctrl-C 看到「已停下」）；不要在跑著 demo 的終端機裡打其他指令。
- [ ] testnet 場：每日額度以 **UTC 日**計，**台北早上 08:00 歸零**。一場兩位客人要 relayer 4 筆、商店 2 筆（上限各 12、4）。開場前不要多開沒有要付款的場次：每開一場付款場次就用掉 1 筆登記。
- [ ] 啟動（第 3 節），看到就緒表全部是綠色或灰色。
- [ ] 打開展示視窗（主持人頁的「開啟展示視窗」），拖到投影的螢幕，用「符合」調大小。

## 3 開場

### 本機

1. 終端機在專案目錄執行 `make demo-local`。
2. 看到「請輸入錢包的密語」時輸入。輸入時畫面不會顯示。
3. 頁面會自動打開（`http://localhost:8402/host`）。配對碼印在終端機上，**只輸入到頁面，不要念出來、不要貼到任何地方**。

### Base Sepolia

1. `make demo-testnet`。依序會問：
   1. sudo 密碼：這台電腦的登入密碼；
   2. 等語音服務載入（約 2～3 分鐘）；
   3. relayer 的密語；
   4. **開場前檢查**（自動）：印出 `preflight:` 開頭的幾行，今天的筆數與餘額。不夠時會停下並說哪一項不夠（第 6.1 節）；
   5. sudo 密碼若再問一次，還是登入密碼；然後錢包的密語。
2. 頁面打開後同上配對。
3. 就緒表裡「relayer 今天」「商店今天」要是綠色；黃色表示不夠一場兩位客人。

## 4 一場的流程

1. 主持人頁選情境「資料研究室」。
2. 按「一起開始」：主持人會依序替客人 A、B 確認委託（這是模擬，主持人扮演客人），再開始兩位客人的場次。
3. 兩位客人的 Agent 會挑商品、報價 0.50，超過自動範圍，要本人核准。核准面板上方會寫「客人 B 也有一筆請購等你核准」。
4. 核准 A：按「用已登記的裝置核准」。
   - testnet：等畫面出現「**錄音中，請唸這一句：**」**之後**才唸大字那一句；只唸那一句，唸完按「唸完了」，再輸入 PIN。
   - 本機：直接輸入 PIN。
5. 按「切換到客人 B」，同樣核准 B。核准有期限（約 2 分鐘），面板上有倒數。
6. 看展示視窗：付款由 Host 依序處理，後面那位會先顯示「排在前一筆付款之後」，接著預留、付款、交付，最後有收據。

## 5 收場

1. 在跑 demo 的終端機按一次 Ctrl-C，等「已停下」。直接關掉視窗也會停下全部。
2. 本機：鏈會保存，下次同一個指令接著用。
3. testnet：Host 還在跑的時候，另開終端機執行對帳（唯讀，查鏈上有沒有未經授權的支出）：

   ```
   P2_PRESENT_DIR=var/p2-testnet/present sh scripts/demo/p2-reconcile.sh var/p2-testnet/reconciliation-$(date +%Y%m%d-%H%M%S).json
   ```

   印出的「未授權新增支出」應是 0。

## 6 出錯時

每一列：看到什麼 → 原因 → 下一步。「找開發者」表示不要自己處理。

### 6.1 啟動時（終端機）

| 看到 | 原因 | 下一步 |
|---|---|---|
| 「127.0.0.1:8402 已有程式在用」 | 上一個 Host 還在跑 | 找到那個終端機按 Ctrl-C；找不到就 `lsof -nP -iTCP:8402` 看是誰 |
| 「127.0.0.1:8545 已有程式在用」（本機） | 上一條本機鏈還在跑 | 同上，`lsof -nP -iTCP:8545` |
| 「/opt/apa-signer/run/signer.sock 是上一次留下的」 | 上次 Signer 沒有正常結束 | 照畫面那行指令執行（`sudo -u apa-signer /bin/rm …`），再重新啟動 |
| 「/opt 的語音服務已在跑」 | 上次沒停乾淨 | `sudo /usr/bin/pkill -TERM -u apa-signer -f /opt/apa-signer/voice/sidecar.py`，再重新啟動 |
| 「語音服務沒有起來」「6 分鐘內沒有就緒」 | 模型載入失敗 | 看 `var/demo-testnet/logs/voice.log` 最後幾行；找開發者 |
| 「relayer 停了」「Signer 停了（密語不對…）」 | 密語輸入錯 | 重新啟動再輸入一次。**想不起密語就停下找開發者**：密語無法找回，也不能繞過 |
| `preflight: 不夠：relayer 今天只剩 …` | 今天（UTC 日）的交易額度用完 | 台北 08:00 後再開場；或改用本機場 |
| `preflight: 不夠：wallet-… 只有 …`／`… 的 gas 只有 …` | 測試幣或 gas 不夠 | 找開發者（領測試幣要另外核准） |
| `preflight: 無法檢查（…）` | 讀不到 relayer 或公開節點 | 會繼續啟動；開場前看就緒表的「relayer 今天」 |
| 「本機鏈沒有起來」「the kept chain has no budget contract」 | 本機鏈的存檔有問題 | 找開發者（不要刪 `var/` 下的任何東西） |
| 「sudo 已過期，/opt 的服務可能還在跑」（停下時） | 停下時 sudo 授權已過期 | 照畫面那行 `sudo /usr/bin/pkill …` 指令執行 |

### 6.2 頁面與配對

| 看到 | 原因 | 下一步 |
|---|---|---|
| 「本人核准需要從 http://localhost:8402/host 開啟」 | 網址是 127.0.0.1 | 改用 `http://localhost:8402/host` |
| 配對碼被別人看到、念出來或貼出去了 | 配對碼外流 | 不要用它；Ctrl-C 重新啟動，用新的配對碼 |
| 就緒表有紅色「Signer」「relayer」「語音服務」 | 那個服務停了 | 看終端機的訊息；通常要 Ctrl-C 重新啟動 |
| 就緒表「relayer 今天」黃色或紅色 | 今天的額度不夠一場或已用完 | 同 6.1 的 preflight |
| 展示視窗寫「主持人頁未連線（停在最後狀態）」 | 主持人頁關了或重新整理中 | 回到主持人頁；必要時再按「開啟展示視窗」 |
| 展示視窗寫「另一個展示視窗正在使用」 | 開了兩個展示視窗 | 關掉多的那一個 |

### 6.3 核准時（核准面板）

| 看到 | 原因 | 下一步 |
|---|---|---|
| 「語音挑戰未通過，這筆已拒絕」（展示視窗：「唸的內容或聲音不符，已拒絕」） | 太早開始唸、唸了別的字、或聲音不像 | 這一筆已拒絕，沒有付款。重新開始這位客人的場次，等「錄音中」再唸 |
| 「核准者還沒有登記聲紋」 | 這位核准人在 testnet 沒有聲紋 | 找開發者（要登記聲紋） |
| 「這位客人還沒有登記核准裝置」 | 這位核准人沒有登記裝置 | 找開發者（要登記裝置） |
| 「已過期」「這次驗證已過期」 | 超過核准期限（約 2 分鐘） | 沒有付款。重新開始這位客人的場次 |
| 「這筆還有一個進行中的驗證」 | 上一次驗證還開著 | 等一下，或按「取消這次驗證」 |
| 「這筆已經有本人決定」 | 這一筆已經核准或拒絕過 | 看面板上的結果即可，不要重做 |
| 「結果確認中，請不要重複操作」 | 正在等 Signer 回覆 | 等；不要再按 |
| 「task 已結束：這筆不能核准」 | 這位客人的場次已結束 | 重新開始這位客人的場次 |

### 6.4 付款時（核准之後）

| 看到 | 原因 | 下一步 |
|---|---|---|
| 「排在前一筆付款之後」 | 正常：付款一次處理一筆 | 等 |
| 「已送出付款，等鏈上確認」很久 | testnet 要等 2 個區塊確認 | 等；不要重新開始（不會重複付款，但會多用額度） |
| 「未付款：預算預留失敗，沒有花錢」（展示視窗：「這筆沒有付款（沒有花錢）」） | relayer 拒絕預留，最常見是今天額度用完 | 終端機會有一行 `relayer` 拒絕的原因；看就緒表「relayer 今天」。今天不要再試 |
| 「沒有付款（錢沒有動）：預算已預留，但付款沒有送出」 | Signer 沒有簽或來不及送 | 錢沒有動。記下時間，找開發者 |
| 「商店回覆沒有接受、沒有送出（商店的說法，鏈上未確認）」 | 商店拒絕這筆付款 | 終端機有一行 `shop:` 開頭的原因；記下來找開發者 |
| 「沒有付款（錢沒有動）：付款授權已過期，鏈上沒有用過」 | 授權過期而且鏈上確認沒用 | 錢沒有動，不用處理 |
| 「鏈上的付款結果對不起來，待人工確認」 | 對帳不一致 | **停下這一場，不要重試**，找開發者 |
| 「已付款，交付失敗，待人工處理」 | 付款成功但商品沒交付 | 錢已付；找開發者 |

## 7 不要做的事

- 不要說出、貼出或寫下任何密語、配對碼、登記碼。
- 不要刪除 `var/` 底下的任何檔案或目錄：Signer 記得做過的每一場，刪了之後的場次會被拒絕。
- 不要用真錢、主網或日常使用的錢包。
- 不要在跑著 demo 的終端機裡輸入其他指令。
- 出錯時不要自己改設定或繞過檢查；照第 6 節，表上沒有就找開發者。

## 8 展示時要照實說的事

- **委託是模擬的**：主持人扮演客人確認委託；真實的是每一筆超過範圍的付款由本人用裝置核准（testnet 還加上語音）。
- **兩位核准人是同一個人**：客人 A、B 的核准人是同一個人、同一台裝置、同一個聲音。
- **付款是依序處理的**：兩位客人同時選購，但 Host 一次處理一筆付款。
- **錢是測試用的**：本機是這台電腦上的測試鏈；testnet 是公開測試網路的測試 USDC。兩者都不是真錢，本機的結果也不能說成 testnet 的結果。
- **Agent 是 fake**：照劇本購物，不是真的模型在判斷。
