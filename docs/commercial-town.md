# 商務城鎮：點一個場域，看它的真實交易

> 2026-10-24，Claude Code。Aaron 10/24：參考「HEART 政策島」（https://puma.taipei/heart-island）的設計方法，「預期之後會有多個商務場景同時在跑動，使用者只要點擊相關場域，就會驅動相應場域實際的交易行為展示……但我們還是保有 pixel art 的特色」。

## 1 從政策島學的

| 政策島的做法 | 用在這裡 |
|---|---|
| 場景是主角：城市鋪滿視窗，標誌、工具列、說明都是浮在上面的圓角卡片 | 像素城鎮鋪滿視窗；產品名稱、場域清單、步驟、核准都是浮動卡片 |
| 編號串起畫面與文字：清單的 01～14 也標在城市的各區 | 每個場域有編號；地圖上的店面招牌與右側清單用同一個編號 |
| 點一項，鏡頭走進那一區，左側出現它的細節卡 | 點一個場域：轉場走進那間店（像素遊戲的「進門」），左側出現它的交易步驟卡 |
| 編輯式排版：小字英文標籤、大標題、一句有色條的引言、事實做成小標籤 | 步驟卡「STEP 03・核准」＋大標題＋一句重點；區塊與交易是小標籤加 ↗ 連結 |
| 米白底、單一強調色（橘）、選中的按鈕是黑色膠囊 | 淺色暖調、單一強調色；保留像素素材本身的顏色 |

## 2 Aaron 的決定（10/24）

- **互動在哪**：主持人頁加「簡報模式」：只留城鎮、場域清單、步驟卡與核准面板，藏起操作表格。點場域就開始那個場域的交易；權限沿用配對後的主持人憑證，安全邊界不變。展示視窗維持只看、不持有權限。
- **同時程度**：被點選的場域跑真實交易（委託確認、核准、付款、交付）；其他場域只有生活感（行人、店員走動），照實標示「示意」。沿用客人 A、B。

## 5 界線

- 只有被點的場域會付款；其他場域的動態不連到任何交易，畫面照實標示。
- 付款仍依序處理；兩位核准人仍是同一人同一裝置（照實說）。
- 素材授權由 Aaron 取得；不在 repo 放未授權的素材。

## 6 進度

- **T1 簡報模式（網頁）**：主持人頁頁首「簡報模式」按鈕（Esc 或左下「離開簡報模式」回到原本畫面；記在這個瀏覽器）。開啟後：淺色暖調、場景置中鋪滿；左欄是品牌卡（AI 幫你買，錢由你決定）與交易步驟卡（每位客人五步，斜體編號、目前這步用強調色；付款後是收據標籤，不再蓋住場景）；右欄是場域清單（01 資料研究室、02 街角咖啡、03 巷口便利商店，狀態「待命／交易中」）與核准面板。點一個場域會切到它的店內，再按「開始這個場域的交易」，等同該場域的一起開始（每位客人先確認委託）。操作表格、配對列、就緒表都收起來。
- 用 fake 主持人截圖確認版面（1440×900、1920×1080）；網頁單元測試與展示視窗瀏覽器測試（show-ui）全過。
- 留給 T2（Unity）：場景外圍的深色底與店內左上角的文字（網路、素材說明）、區域標籤改成白色編號膠囊。

### T2 城鎮與掀開屋頂（Aaron 選 B：屋頂原地掀開，鏡頭拉近）

- **素材**：Modern Exteriors v42.3 的 32×32 圖（Aaron 下載的包）。`limezu-assets.txt` 多了 `x-*` 一批與授權檔；`import-limezu.sh` 的 `LIMEZU_DIR` 要同時有 `Modern_Interiors_v41.4/` 與 `Modern_Exteriors_v42.3/`（已在的檔案相同就不再複製）。建置時把每一塊切成自己的檔（`Assets/LimeZu/_cut`，不進 git），build 只帶小塊不帶整張大圖（Web build 15 MB）。`5_Floor_Modular_Buildings` 高 8288 px，超過批次模式 Unity 的 8192 上限，所以建置器自己讀 PNG（8-bit RGBA）；切出來的 31 塊與 PIL 裁的逐像素相同。
- **城鎮**（`Resources/Town/town.json`，資料檔，改城鎮不用改程式）：64×44 格的地圖，一條馬路、斑馬線、人行道、路燈、長椅、樹、兩台車。三間店的外觀與室內同寬（12 格）：01 資料研究室（灰屋頂、紅磚辦公室門面）、02 街角咖啡（綠屋頂、Bakery 店面）、03 巷口便利商店（MARKET 外觀，屋頂分三段補到蓋住牆頂）。每間店屋頂上有白色膠囊：橘色編號＋店名，與右側清單同一個編號。
- **掀開屋頂**：店內房間就放在它那間店的位置；Unity 有兩個視角：城鎮（三間都有屋頂）與某一間店（它的屋頂與名稱膠囊淡出，鏡頭拉近）。鏡頭永遠是整數倍：城鎮用放得下城鎮框（34×30 格）的最大整數倍（至少 1 倍，窄螢幕裁切而不糊）；店內用放得下房間（15×10 格）的最大整數倍；兩者之間的移動，倍數一格一格跳、鏡頭中心平滑移動，約 0.55 秒。房間的標題與區域標籤在城鎮視角關掉（不會從屋頂外露）。
- **頁面**：簡報模式且 Unity 有城鎮時，畫布鋪滿整個視窗，Unity 自己選整數倍；頁面把兩欄卡片之間沒被蓋住的範圍告訴 Unity，目標放在那個範圍的中間。進簡報模式先看城鎮；點清單的場域或直接點地圖上的店，就進那間店（屋頂掀開），再按「開始這個場域的交易」才開始；「← 回到城鎮」回去。品牌卡加上 LimeZu 的素材說明。
- **界線**：Unity 的點擊只回報「點了哪間店」，由頁面決定；進店不會開始交易。沒有城鎮的舊 build 照舊（頁面只在 bridge 說 `town=1` 時送 View）。一般（非簡報）頁面維持店內視角，周圍看得到鄰居。
- **review 修正**：頁面送的「沒被蓋住的範圍」原本 Unity 讀不到（JsonUtility 不會把 x/y/width/height 填進 Rect），城鎮一直以整個畫布置中，改用自己的欄位類別；範圍改在使用時才依當下畫布高度翻轉（重新載入簡報模式時畫布會在訊息之後才變大）；沒有 Exteriors 素材的 build 不說有城鎮；城鎮視角下點擊不再同時選到屋頂下的客人；畫布被隱藏（寬高 0）時鏡頭不動；建置器的 PNG 讀取遇到不認得的 filter 或資料不足就停；這個 build 沒有房間的場域，頁面留在城鎮視角而不是掀開別間的屋頂；收到 Unity ready 時重畫場域清單。
- **驗證**：Unity EditMode 21（新增 PNG 讀取 2：與 Unity 寫出的 PNG 逐像素相同、截斷的檔拒絕）、PlayMode 36（TownTests 6：房間在店裡、自己的屋頂掀開、城鎮與返回、點擊只回報、地面依檔案順序畫、城鎮放在沒被蓋住的範圍中間、View 與換房間不論先後鏡頭都停在新房間；每次也檢查整數倍與像素對齊）全過；網頁單元測試 144 全過（新增 View 等到有城鎮的 build 就緒才送、場域點擊只收合法名稱）；瀏覽器檢查 ux3-ui、show-ui、dual-ui 全過。fake 主持人截圖（1920×1080、1440×900）：城鎮、點地圖上的便利商店進店、回城鎮、從清單進咖啡店、一般頁面。
- **第二輪（Aaron 10/27：「看起來是非常簡陋，需要能做到 limezu.itch.io/modernexteriors 所給的範例這種精緻度」）**：改用素材包的單件圖（singles）把街道做細：有路緣的馬路與車道線、斑馬線與紅綠燈、人行道上的路燈、長椅、消防栓、郵筒、停車計時器、花箱、電話亭、鴿子，有石框的草地花圃與樹。三間店換成素材包現成的建築並裁成能蓋住房間的高度：01 是 LIME CORP 辦公大樓（屋頂太陽能板與空調、招牌樓層、入口），02 是兩層樓的 Bakery 店面（屋頂有空調、風扇、通風口），03 是商場的紅色店面（取右邊 12 格）。03 旁邊是廣場：咖啡杯造型的小亭、噴水池、長椅、盆栽樹。街上站著九位路人（Modern Interiors 的現成角色，不會動），右側清單下寫「街上的行人只是示意；只有你點的場域會真的交易」。名稱膠囊改小，放在各建築的頂端上方。整張地圖往上移 4 格，進便利商店時下方仍是人行道。路人用到 Modern Interiors 的角色 02～20：`LIMEZU_DIR` 裡的 `Modern_Interiors_v41.4/` 要有完整的 `2_Characters/Character_Generator/0_Premade_Characters/32x32/`。
- **已知限制**：1440×900 時城鎮是 1 倍，部分在卡片底下（以 1920×1080 為準）；掀開屋頂後房間沒有側牆；展示視窗（T4）還是只有店內；生活感（T3：路人與店員走動）還沒做。show-ui 第二輪跑了 2 次，其中 1 次「主持人頁重新載入後展示視窗重新回報」超時（另一次全過），原因未查明，可能是兩個 Unity 同時載入較重的城鎮。
